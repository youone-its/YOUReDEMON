# Project Folder Structure

This document outlines the folder organization for **YOUReDEMON** following Godot's recommended practices.

## Overview

```
YOUReDEMON/
├── project.godot
├── icon.svg
├── characters/
│   ├── player/
│   ├── enemies/
│   └── LiveChat/
├── levels/
├── ui/
│   └── menus/
├── autoload/
├── shader/
└── assets/
    ├── sprites/
    └── textures/
```

## Folder Descriptions

### `/characters/`
Contains all character-related scenes and scripts (player, enemies, NPCs).

- **`/characters/player/`** - Player character files
  - `player.tscn` - Player scene
  - `player.gd` - Player movement and logic script
  
- **`/characters/enemies/`** - Enemy types (organize by subfolder)
  - Example: `/characters/enemies/goblin/` for goblin scene, script, and animations
  - Example: `/characters/enemies/slime/` for slime scene, script, and animations

- **Future**: `/characters/npcs/` for non-playable characters

### `/levels/`
Contains game levels, maps, and world scenes.

- Example: `/levels/forest.tscn` - Forest level
- Example: `/levels/town.tscn` - Town level
- Keep level-specific assets close to the level scene when possible

### `/ui/`
User interface elements, menus, and HUD components.

- **`/ui/menus/`** - Main menu, pause menu, settings, load screens
  - `init.tscn` - Initialization scene
  - `load_menu.tscn` - Load game menu
  - Scene scripts kept together with their `.tscn` files

### `/autoload/`
Global singleton scripts that auto-load with the game.

- `GameData.gd` - Global game state and save data management
- Add other autoload scripts here (audio manager, scene manager, etc.)

### `/shader/`
Custom shader files for visual effects.

- `light.gdshader` - Lighting shader
- Keep shader-related resources here

### `/assets/`
Shared resources used across multiple scenes.

- **`/assets/sprites/`** - Sprite sheets and textures
  - **`/assets/sprites/player/`** - Player character sprites
  - **`/assets/sprites/world/`** - World tiles, props, decorations
  - **`/assets/sprites/ui/`** - UI backgrounds and icons
  - `TX Player.png` - Player sprite sheet
  - `TX Props.png` - Props sprite sheet
  - `TX Tileset Grass.png` - Tileset for grass

- **`/assets/textures/`** - Non-sprite textures (lighting, effects)

- **Future folders**:
  - `/assets/audio/` - Music and sound effects
  - `/assets/fonts/` - Font files

### `/addons/` (when needed)
Third-party plugins and extensions from the Asset Library.

## Naming Conventions

### Files and Folders
- Use **snake_case** for files and folders: `player_attack.gd`, `forest_level.tscn`
- Exception: C# scripts use **PascalCase** to match class names

### Node Names
- Use **PascalCase** for node names in scenes: `Player`, `CollisionShape2D`, `AnimatedSprite2D`
- Matches Godot's built-in node naming convention

## Best Practices

1. **Keep related assets together**: Place sprites, scripts, and scenes for a character in the same folder
2. **Group by feature**: Organize by what something represents (player, enemy, level) not by file type
3. **Shallow hierarchy**: Avoid deeply nested folders (max 3-4 levels deep)
4. **Consistent naming**: Be consistent with naming patterns across the project

## Adding New Content

### New Enemy Type
```
/characters/enemies/zombie/
├── zombie.tscn
├── zombie.gd
└── zombie_spritesheet.png (if character-specific)
```

### New Level
```
/levels/
├── dungeon_01.tscn
└── dungeon_01_tilemap.png (if level-specific)
```

### New UI Menu
```
/ui/menus/
├── inventory_menu.tscn
└── inventory_menu.gd
```

### New Autoload Script
```
/autoload/
└── audio_manager.gd
```

### Shared Asset
```
/assets/sprites/
└── TX New_Tileset.png
```

## Version Control

- All `.import` files are automatically generated by Godot
- Commit both the source asset and its `.import` file
- Use `.gdignore` in folders you want Godot to ignore (like `/docs/`)
